# 存储 v3 恢复夹具

`recovery.json` 保存可直接落盘的 UTF-8 字符串。`base`、`target` 各是完整已发布快照，`journal` 含完整提交记录。哈希对字符串编码后的字节计算。夹具包含改名与富文本、删除、新建、月度 JSONL 分片、数组顺序、未知字段和 `null`。所有数据均为合成内容。

`materializeRecoveryFixture(root, scenario)` 在新的空临时目录中生成一个崩溃状态。`disk.index` 选择起始快照，`applyAfter` 将部分文件替换或删除，`omit` 去掉暂存文件，覆盖字段模拟外部改写。`disk.participant` 是需注入到宿主测试中的通用参与者状态，由测试驱动提供。

阶段 B 用同一套场景运行真实恢复器，检查 `expected.action`、最终活动代次、参与者结果、写入及网络门控和证据保留。`writesAndNetwork: "open"` 仅表示恢复结束后可接受新请求。历史成功通知不重放。`"blocked"` 要求恢复期间无成功通知、无 ACK、无后续写入且保留证据。`published-once` 包含原来已经成功的发布，重启不得重复产生事实。`activeGeneration: null` 表示应用尚未取得可安全使用的活动快照。

对每个可恢复场景再重开一次，核对正常快照的完整字节、文件集合、代次和参与者次数。对于保护场景，核对原数据、暂存和参与者状态仍在，并且无法正常打开网络端口。对真实实现另以故障注入覆盖以下输入。可从夹具复制数据，各次执行使用新的临时目录。

| 注入 | 预期 |
| --- | --- |
| 另一进程持锁、进程强杀后残留诊断文件、同目录路径别名 | 活跃锁拒绝第二写入者。原进程终止后按平台锁规则恢复，不删除活跃锁 |
| `fsync`／目录入口刷新失败、磁盘满、设备拔出 | 决策前保持旧数据。决定后保留证据，恢复与核对完成前禁止成功确认。活动目录不可用时不创建空库 |
| 路径越界、符号链接、大小写冲突、未知必需扩展 | 拒绝打开写入，不读取根外内容，不删除原文件 |
| 候选已校验但未激活、源内容变化、活动指针写入时中断 | 保持或恢复唯一活动源，拒绝过期确认。激活后只承认已校验的目标，旧源仍在 |
| 跨卷复制附件中断、目标缺附件、激活后目录不可读 | 未激活候选不影响旧源。活动源损坏时进入保护，禁止回写旧源 |
| 迁移中收到网络请求、旧格式导出后启用原同步身份 | 前者被门控且发送端队列保留。后者需要协调恢复，不能继续使用旧游标 |
| `.md` 被改写、导出失败、关闭持续发布 | 正本与代次不受影响。失败可补写最新已提交的副本，关闭后停止派生写入 |
| 同一 UTC 月界不同时区、超大正文及大量附件 | 分片结果稳定，原始时间保留，重组顺序不变。记录耗时和峰值内存 |

阶段 A 的夹具测试检查字节、哈希和合成磁盘状态。真实恢复与平台持久性由阶段 B 验证。
